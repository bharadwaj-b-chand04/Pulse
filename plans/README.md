## Findings considered and rejected

- **Autofill Patient ID on the entry form from the Patient's session** (2026-09-28): rejected. Patients hold no `RECORDS_WRITE`, so a Patient can't file at all; the real fix was hiding the button from Patients and prefilling from the staff record view (done in the working-tree fix).
- **Stray `frontend/frontend/.next` makes `npm run lint` report 231 errors locally** (2026-09-28): not a plan. It's an ignored build leftover from 2026-09-23; ESLint ignores `.next/**` only at the top level. Move that directory out of the repo.
- **Patient search for Provider Staff** and **patient-uploaded documents** (2026-09-28): direction options, not defects. The second contradicts "providers contribute" and needs an ADR first.

- **Hardcoded `pulse_app`/`pulse_app` dev password in `backend/app/db/migrations/versions/0001_roles_and_pg_trgm.py`**: not a finding — it's a documented dev/demo credential matching `compose.yaml`'s already-committed value, in a project that per `.claude/rules/clinical-safety.md` never holds real patient data. The migration's own docstring explains the choice. Flagging real secrets in academic-project seed/dev config would be noise.
- **`ALTER DEFAULT PRIVILEGES` vs. explicit per-table `GRANT` for `audit_event`'s append-only rule**: the db track already made and documented this call correctly (explicit table-scoped grant deferred to the Phase 3 migration that creates `audit_event`, to avoid capping every future table at INSERT/SELECT). Not a finding, it's the right call, already recorded in the migration docstring.
- **No `backend/app/main.py` yet**: not a bug, a known and already-flagged Phase 0 gap (the platform track's Dockerfile CMD targets `app.main:app` and says so explicitly). It's the next integration step, not something for an executor to guess at — will be added directly, not through this plans/ process.
- **Zero tests anywhere in the repo**: expected at this stage — no `pyproject.toml`/test harness exists yet for backend, and frontend has no test runner configured either. Not a Phase-0-scoped finding; becomes real once a harness lands.
- **`@stub` decorator (`backend/app/core/stub.py`) ignores the wrapped function's body**: by design — `@stub`'s whole point is to return fixture data unconditionally while FastAPI still inspects the original function's signature (via `functools.wraps`' `__wrapped__` chain) for path/query param validation and OpenAPI docs. Confirmed correct, not a finding.
- **Ponytail / over-engineering pass** across everything landed (`core/`, `db/`, Dockerfiles, compose.yaml, frontend skeleton): nothing found. No interfaces with one implementation, no premature config, no speculative abstraction — `Page[T]`, `PulseError`, the request-id contextvar, the async session factory are all the minimum shape needed and match the "contracts before implementations" rule in `.claude/rules/backend.md`. Worth stating explicitly rather than implying by silence: checked, clean.
